## 1. 共通

- 管理画面の操作で、会員・ポイント・掲載内容が変わるものは、すべて操作ログ（`admin_audit_logs`）に残す（誰が・いつ・何に・何をしたか）
- 会員の個人情報（口座番号など）は、管理画面でも必要な範囲だけ表示する。口座番号は末尾3桁以外を伏せる（全桁は換金の CSV だけ）

## 2. 案件の表示設定（管理画面 `/campaigns`）

案件の中身（名前・ポイント・期間など）は GF Rewards の案件 API から15分ごとに取り込むので、管理画面では変えない。運営が決めるのは表示の仕方だけ。

| 設定 | 内容 |
|---|---|
| 非表示 | オンにすると、ASP 側で掲載中でもサイトに出さない |
| おすすめ | オンにすると、一覧の先頭とトップのおすすめ枠に出す |
| 並び順 | 数字が小さいほど前に出す（既定 0）。並びは「おすすめ → 並び順 → 新しい順」 |

- 一覧の絞り込み: 掲載状態（サイトに掲載中／ASP 側で停止・未開始／掲載終了／非表示）、名前・案件IDの検索
- 一覧で案件ごとに、ASP の状態・掲載期間・最大ポイント・最終取り込み日時を表示する
- 変更は操作ログに残す（`campaign.update_display`）

## 3. イベント（管理画面 `/events`）

| 項目 | 必須 | 内容 |
|---|---|---|
| タイトル | ○ | 100文字まで |
| 開始日時 | ○ | |
| 終了日時 | | 開始日時より後 |
| 形式 | | 「オンライン」など。50文字まで |
| 概要 | | 一覧のカードに出す。200文字まで |
| 本文 | | 詳細ページに出す |
| 注意事項 | | 詳細ページに出す |
| サムネイル URL | | https のみ |
| オープンチャット URL | | https のみ。参加した会員にだけ見せる |
| 並び順 | | 数字が小さいほど前（同じなら開始日時順） |
| 参加上限人数 | | 空なら上限なし |
| 参加ポイント | | 参加を確認した会員に付与するポイント（0 なら付与しない） |
| 状態 | ○ | 下書き／公開／終了 |

- 下書きはサイトに出ない。公開にするとイベント一覧・詳細に出る
- **終了日時（なければ開始日の終わり）を過ぎた公開中のイベントは、自動で「終了」として扱う**（一覧に残し、詳細に「終了しました」と出して参加ボタンを消す。トップには出さない）。運営が手で「終了」にしてもよい
- 削除できるのは下書きで参加者がいないものだけ。公開したものは下書きに戻すか終了にする（会員がリンクを持っている可能性があるため）
- 画像のアップロードは当面しない（サーバに状態を持たないため。必要になったら S3 に置く）
- 登録・変更・削除は操作ログに残す

### 3.1 参加の管理（2026-11-20 方針変更: 参加者にインセンティブを渡すため、サイトで参加を受け付ける）

参加したかどうかは専用のテーブル（`event_participants`、イベントと会員の組で1行）で判定する。

1. **参加する**: 会員がイベント詳細の「参加する」を押す（LINE ログイン必須）
   - 公開中で、開始前のイベントだけ参加できる（開始後・終了後・下書きは不可）
   - 参加上限人数に達していたら「満員」と表示して受け付けない（同時に押されても上限を超えないよう、DB のロックで数える）
   - 停止中・退会済みの会員は参加できない
   - 参加すると、オープンチャットの URL が表示される（**オープンチャットの URL は参加した会員にだけ見せる**）
2. **参加をやめる**: 開始前なら会員が自分で取り消せる（枠が空く）。取り消し後にもう一度参加してもよい
3. **参加の確認とポイント付与**: イベント後に管理画面の参加者一覧で、実際に参加した会員を選んで「参加を確認」する
   - 参加ポイントが設定されていれば、その場で確定ポイントとして付与する（ポイント履歴に「イベント参加: <タイトル>」と表示）
   - 1人1イベント1回だけ付与する（二重付与しない）
   - 参加しなかった会員は「不参加」にできる（ポイントなし）
   - 操作ログに残す

| 参加の状態 | 意味 |
|---|---|
| 参加予定（joined） | 会員が参加ボタンを押した |
| 取り消し（cancelled） | 開始前に会員が取り消した。上限人数に数えない |
| 参加済み（attended） | 管理者が参加を確認した。参加ポイントを付与済み |
| 不参加（absent） | 管理者が不参加とした |

- 一覧・詳細には「残り◯人」（上限があるとき）と、自分が参加予定かどうかを表示する
- 管理画面の参加者一覧は CSV でも出せる（会員ID・表示名・状態・参加日時。個人情報は含めない）

## 4. 会員（管理画面 `/members`）

### 4.1 検索・詳細

- 検索: 会員ID（`uid`）、表示名（部分一致）、状態（有効／停止中／退会済み）
- 詳細: 状態・登録日・最終ログイン、ポイント（利用可能・判定中）、ポイント履歴、換金申請、成果（保留を含む）、最近の案件クリック、口座（口座番号は伏せる）

### 4.2 停止・再開

- 停止には理由（255文字まで）が必須。理由は操作ログに残し、会員には表示しない
- 停止中の会員は
  - ログインできない（LINE ログイン後にエラー画面）
  - ログイン中だった場合も、次の API 呼び出しでログアウトされる
  - 案件への遷移・口座の登録・換金申請ができない
  - 成果通知は台帳に記録する（扱いは運営が調査して決める）
- 再開すると元どおり使える。退会済みの会員は停止・再開できない

### 4.3 ポイントの手動調整

- 付与（正の数）または減算（負の数）。理由（255文字まで）が必須で、会員のポイント履歴に「運営による調整」として理由も表示する
- 減算で利用可能ポイントがマイナスになる調整はできない
- 調整はすぐに確定する（判定中にはしない）。1回の上限は ±100,000 ポイント
- 退会済みの会員には調整できない
- 操作ログに残す（`points.adjust`）

## 5. 成果通知（管理画面 `/postbacks`・`/conversions/held`）

- 受信ログ: 受信日時・結果（付与／判定中／否認／重複／保留／署名不一致／パス違い／IP 不一致など）・cv_id・送信元 IP・応答。結果と cv_id・日付で絞り込める。パラメータは詳細で確認できる
- 保留した成果: 保留の理由・通知ポイント・案件情報のポイント・会員・案件。内容を確認して「保留を解除」できる（`php artisan postback:release` と同じ動き。承認済みなら通知ポイントで確定、未承認なら判定中のまま）
- 会員が見つからない・退会済みの成果は解除できない。解除は操作ログに残す

## 6. 会員の退会（マイページ `/mypage/leave/`・`POST /v1/me/leave`）

- マイページから、注意事項に同意して退会する
- **手続き中の換金申請（申請中・振込待ち）があるときは退会できない**（振込が終わってから）
- 退会すると
  - 残っているポイント（利用可能・判定中とも）は失効する。台帳はそのまま残し、退会後に届いた成果通知には「退会ユーザー（2）」を返す
  - ログアウトし、同じ LINE アカウントでは再登録できない（不正対策。LINE のユーザーID は残す）
  - 表示名・アイコンは消す。口座情報は同一口座の検知のために残す（画面には出ない）
- 退会は取り消せない（運営に依頼しても戻さない。仮）

## 7. 案件一覧のカテゴリ絞り込み（フロント `/campaigns/`）

- 掲載中の案件のカテゴリをタブで並べ、選ぶとそのカテゴリだけ表示する（「すべて」が既定）
- カテゴリは GF Rewards の案件 API の値をそのまま使う（`GET /v1/campaign-categories`）
- URL に `?category=` を付けて共有できる
