# ポイフォ｜トップ画面構成・機能仕様（初期版）

- 作成日：2026年11月19日
- 対象：ポイフォ（ポイントサイト）のトップ画面／初期リリース
- 目的：開発担当者とトップページの画面構成・導線・運用範囲を共有する
- 方針：シンプル・スマホ優先。ポイント案件を主役にしつつ「担当サポート」「みんなでポイ活」を訴求する

## 1. サービスコンセプト

**ひとりじゃない、あたらしいポイ活。**

通常のポイントサイトのように自由に案件を探せることに加え、公式LINEで担当スタッフに相談でき、イベントを通じてみんなでポイ活に取り組めるサービス。

### コア機能

1. ポイント案件を探す・利用する（GF Rewards連携を想定）
2. 担当サポート（ポイフォ公式LINEへ遷移し、担当者が対応）
3. イベント（サイトにイベント情報を掲載し、LINEオープンチャットへ誘導）

## 2. 決定済みの運用方針

| 項目 | 方針 |
|---|---|
| 担当サポート | サイトの「担当サポート」から**公式LINEへ遷移**。相談・初回面談の日程調整・追加フォローはLINE上で担当者が行う |
| 会員登録とLINE | 会員登録完了後に公式LINE追加を案内。LINE追加は任意で、未追加でも案件を利用できる想定 |
| イベント | **サイト内にイベント紹介・一覧機能を設ける** |
| イベント参加導線 | イベント詳細のボタンから**LINEオープンチャットのURLへ遷移** |
| イベント運営 | オープンチャット内の**サブトークルームをイベントごとに作成**して進行・案内する方針 |
| イベント告知 | サイトで自由に閲覧・参加でき、担当スタッフから公式LINEで個別案内も行う |
| イベント登録 | 運営側がイベント情報を登録・更新する |
| 初期開発 | 独自のチャット、面談予約の開発は**原則不要**。イベントの参加受付・上限人数・参加ポイントは 2026-11-20 に方針変更して実装する（[admin-and-member-spec.md](admin-and-member-spec.md) 3.1） |

> **重要：** 以前検討していた「サイト内でイベント参加申込」「サイト内のZoom参加URL表示」は、今回の決定方針に合わせて初期スコープから外す。イベント参加の管理はオープンチャット側で行う想定。ただし、LINEオープンチャットのサブトークルームへの直接リンク可否・参加条件・管理機能は実機で確認すること。

## 3. トップ画面の構成（スマホ優先・上から順）

### ① ヘッダー

- ポイフォのロゴ（採用済みロゴを使用）
- ログイン前：「無料会員登録」「ログイン」
- ログイン後：「マイページ」／メニュー
- メニュー例：案件を探す、イベント、担当サポート、ポイント履歴、ポイント交換、ヘルプ

### ② メインビジュアル／ファーストビュー

- キャッチコピー：**「ひとりじゃない、あたらしいポイ活。」**
- 補足文案：「ポイントを貯める楽しさに、相談できる安心と、みんなで取り組むワクワクを。」
- ログイン前の主CTA：「無料で始める」
- ログイン後の主CTA：「ポイントを貯める」
- デザイン：ティファニーブルー系を基調、余白があり親しみやすいシンプルなデザイン

### ③ 案件を探す（主要コンテンツ）

- おすすめ案件をカード形式で表示
- 案件名・画像・獲得ポイント・簡単な説明を表示
- 「すべての案件を見る」への導線
- カテゴリ別表示や検索はGF Rewardsの提供機能・実装仕様に合わせて調整
- 案件の詳細・利用導線はGF Rewardsとの連携仕様確定後に整理

### ④ 担当サポート

**見出し案：** 「困ったときは、担当スタッフに相談。」

- 説明：「ポイントの貯め方や案件の進め方をLINEで気軽に相談できます。」
- CTA：「公式LINEで相談する」→ ポイフォ公式LINEへ遷移
- 初回面談の日時もLINEで調整する旨を案内
- サイト内チャット・独自予約カレンダーは実装しない
- 登録完了画面とマイページにも公式LINEへの導線を置く

### ⑤ みんなでポイ活（イベント）

**見出し案：** 「みんなでポイ活！」

- 説明：「ゲーム案件などに、みんなで楽しく挑戦。イベント情報をチェックしよう！」
- トップ画面では開催予定のイベントを最大2〜3件ほど表示
- イベントカード：イベント名／開催日時／概要／開催方法／「詳しく見る」
- CTA：「イベント一覧を見る」→ イベント一覧ページ
- イベント詳細：内容、日時、注意事項、オープンチャットへの参加導線
- 参加CTA：「オープンチャットで参加する」→ 設定されたLINEオープンチャットURL
- イベントごとの会話や案内はオープンチャットのサブトークルームで運用する想定

### ⑥ ポイフォの特徴（3つ）

1. **自由にポイ活**：興味のある案件を自分のペースで利用
2. **担当者に相談**：公式LINEで気軽にサポートを受けられる
3. **みんなで楽しむ**：イベントやオープンチャットで一緒に取り組める

### ⑦ 初めての方へ／よくある質問

- ポイントの貯め方
- ポイント獲得条件・反映について
- 担当サポートの利用方法
- イベント参加方法
- 詳細はFAQ・利用ガイドへ遷移

### ⑧ フッター

- サービスについて／利用規約／プライバシーポリシー
- 運営者情報／お問い合わせ／ヘルプ
- その他必要な表記は公開前に法務・運営面で確認

## 4. 画面遷移（概要）

```text
トップページ
├─ 案件を探す → 案件一覧／案件詳細 → 広告利用
├─ 担当サポート → ポイフォ公式LINE → 担当者が個別対応・日程調整
├─ イベントに参加する → イベント一覧 → イベント詳細
│                                      └─ LINEオープンチャットURL
│                                          └─ イベントごとのサブトークルームで案内
├─ マイページ → ポイント残高／履歴／交換／LINE導線
├─ 利用ガイド・FAQ
└─ 新規登録／ログイン
```

## 5. 初期実装に必要な最低限の管理機能

### イベント情報の登録・編集

| 項目 | 内容 |
|---|---|
| イベントID | 内部管理用 |
| タイトル | イベント名 |
| 概要・詳細 | 内容、対象者、進め方 |
| 開催日時 | 日付・開始時間・終了予定 |
| 開催形式 | オンライン等 |
| サムネイル | 一覧表示用（任意） |
| オープンチャットURL | 参加ボタンの遷移先 |
| 公開状態 | 下書き／公開／終了 |
| 表示順 | トップ画面・一覧の順序調整（任意） |
| 注意事項 | 成果条件や参加上の注意 |

- トップ画面のイベント表示は**公開中かつ開催予定**のものを優先。
- 管理者がイベントを追加・編集・終了できる構成。
- 参加人数・申込・キャンセル・Zoom URL配布等のサイト内管理機能は初期実装しない。

## 6. 会員登録後の導線

1. メール等で会員登録
2. 登録完了画面に「ポイフォ公式LINEを追加」の案内を表示
3. 同じ画面に「ポイントを貯める」導線も用意
4. 公式LINEでは担当者が相談・面談日程調整などを対応
5. LINE未追加でもサイトの基本機能は利用可能とする想定

※登録時の入力項目・本人確認・ポイント交換条件は別途確定。

## 7. ブランド・ロゴ・カラー仕様（過去チャットの決定事項を反映）

### 7-1. ブランド基本情報【決定済み】

| 項目 | 仕様 | ステータス |
|---|---|---|
| サービス名称 | **ポイフォ** | 確定 |
| 英語表記 | **POIFO** | 確定 |
| ネーミングの由来 | **POINT × FOLLOW** | 確定 |
| ブランドコピー | **あなたのポイ活を、フォロー。** | 確定 |
| トップページ訴求コピー | **ひとりじゃない、あたらしいポイ活。** | サイト構成で採用した訴求案 |
| 基調色 | **ブラック × ティファニーブルー系** | 色の方向性は確定 |
| ロゴ | **過去チャットで採用済みのシンプルな文字ロゴ（ティファニーブルー版）** | デザイン採用済み |
| キャラクター | **使用しない** | 確定 |

※ブランドコピー「あなたのポイ活を、フォロー。」とトップの訴求コピー「ひとりじゃない、あたらしいポイ活。」は用途が異なるため、混同しない。

### 7-2. ロゴ使用ルール

- **必ず過去チャットで採用した既存ロゴを使用**。サイト開発時にロゴを描き直したり、別フォントで似せて再現したりしない。
- シンプルで可愛らしい・親しみやすい**文字ロゴ**。重すぎる太字、キャラクター、不要な装飾は避ける。
- 原則としてヘッダー左側に配置。PC・スマホともに縦横比を維持し、余白を確保する。
- 白／明るい背景上では採用済みのティファニーブルー版を優先する。濃色背景向けの反転版は必要に応じて**元デザインから正規に書き出す**。
- favicon、OGP、SNSアイコンは**元のロゴ資産を基準**に別途作成する。文字の形状やデザインを改変しない。
- **ロゴ原本の画像ファイルはこのMDには未添付**。実装担当には採用済みの原本（PNG・SVGなど）を別途共有すること。

### 7-3. カラーパレット

過去チャットで**「ティファニーブルー系＋ブラック」**までは決定済み。ただし、採用済みロゴの画像から抽出された**正確なHEX値は会話記録では確認できなかった**。以下はサイト実装のための**暫定UIカラー案**であり、ブランドカラーの確定値ではない。ロゴ原本を受領後、最優先で実色に合わせて修正する。

| 用途 | 暫定HEX | 運用 |
|---|---|---|
| メイン／アクセント（ティファニーブルー系） | `#81D8D0` | **暫定**。ロゴ原本に合わせて更新 |
| ブランドの濃い文字色 | `#172A2A` | 暫定。見出し・可読性確保 |
| 本文テキスト | `#222222` | 暫定。基本ブラック系 |
| 背景 | `#FFFFFF` | 白を基本とする |
| 薄いブルー背景 | `#E7F8F6` | 暫定。ヒーロー・サポート案内など |
| 境界線 | `#E6EAEA` | 暫定。カードの枠線 |
| サブテキスト | `#667575` | 暫定。補足説明 |

- ティファニーブルーを**全面に塗りすぎない**。白ベースにアクセントとして使う。
- 白字＋薄いティファニーブルーの組み合わせは可読性が低くなりやすいため避ける。主要CTAは十分なコントラストを確保した濃色文字または濃い背景色を用いる。
- ポイント獲得数・成果ステータスなどの重要情報は、色だけでなく文字でも表す。

### 7-4. タイポグラフィ・パーツ

- フォントの**正式な書体名は未確認**。ロゴの書体を推測して指定しない。
- UI本文には読みやすい日本語サンセリフ（例：`Noto Sans JP`, `Hiragino Kaku Gothic ProN`, `sans-serif`）を**仮候補**とする。実装時に最終選定。
- 過度に太い見出しは避け、`font-weight: 500〜600`程度を基本候補とする。文字ロゴ自体は画像資産を使用する。
- カード・ボタンは適度な角丸、フラットで清潔感のある表現。強い影・過度なグラデーション・キャラクター装飾は避ける。
- スマホ優先で、案件カードの情報（案件名・ポイント数・条件）が最も見つけやすい階層にする。

### 7-5. 実装用CSS変数（暫定）

```css
:root {
  /* ブランドロゴ原本を確認後、最終確定すること */
  --color-brand: #81D8D0;
  --color-brand-soft: #E7F8F6;
  --color-heading: #172A2A;
  --color-text: #222222;
  --color-muted: #667575;
  --color-border: #E6EAEA;
  --color-bg: #FFFFFF;
}
```

### 7-6. 制作前の確認項目

- [ ] **採用済みティファニーブルー版ロゴの原本を受領**（可能ならSVG、なければ高解像度PNG）
- [ ] ロゴから実際のメインカラーHEX値を抽出し、上記の暫定パレットを更新
- [ ] ロゴ余白、最小表示サイズ、白背景／濃色背景での見え方を確認
- [ ] favicon／OGPの素材が必要か確認
- [ ] 本文フォント・見出しフォントを最終決定

## 8. デザイン・UI方針

- スマートフォンファースト、PCにも対応
- ロゴは採用済みのものを使用
- ブランドカラーはティファニーブルー系
- 可愛さ・親しみやすさと信頼感の両立。過度に太いフォントや装飾を避ける
- 案件が主役。LINEサポートとイベントは目につくが邪魔にならない配置にする
- トップに全機能を詰め込まず、一覧・詳細ページへ分ける

## 9. 今後確認する事項（未確定）

1. **LINEオープンチャットの仕様確認**：サブトークルームの作成・参加導線、イベントごとの案内手順、直接リンクの可否。実際に運用テストを行う。
2. **URLの持ち方**：イベントごとにサブトークルームへ直接誘導できるか。できなければ共通オープンチャットURL＋参加後の案内で対応。
3. **イベント参加者の把握**：サイト側で人数・会員IDを追跡しない前提で問題ないか。必要なら後から拡張。
4. **公式LINEの担当割当**：会員IDとの紐づけ・担当振り分け方法（初期は手動運用を想定）。
5. **GF Rewards連携**：案件表示、成果反映、ポイント管理等の提供範囲とAPI／ポストバック仕様。
6. **ポイント交換**：交換先、最低交換額、運営フロー。
7. **イベント取り扱い案件の条件**：広告主・ASPの規定に抵触しないか事前確認。ポイント付与は条件達成・成果承認が前提。

## 10. 初期スコープの結論

**作るもの**：トップページ、案件導線、会員機能、公式LINEリンク、イベント一覧／詳細、運営側のイベント登録・編集機能、基本的な案内ページ。

**作らないもの**：サイト内チャット、独自面談予約カレンダー、イベント申込・参加者管理、イベントごとのZoom配信機能、イベント自動リマインド。

サイトは案件利用と情報発信に集中し、**個別サポートは公式LINE、イベントのコミュニケーションはLINEオープンチャット**に分担する。
