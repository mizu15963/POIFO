# ポイフォ｜画面仕様

- 作成日: 2026年11月21日（[top-page-spec.md](https://github.com/mizu15963/poifo/blob/87ebcb3/docs/specs/top-page-spec.md) の画面構成を引き継いで作り直し）
- 状態: 実装済みの画面を書き起こしたもの。2026-11-26 に、参考サイト（大手ポイントサイトの会員版）の画面遷移に合わせて構成を組み直し、実装した（[2.1](#21-参考サイトの画面との対応)）
- 機能のルール（ポイント・換金・イベントなど）: [functional-spec.md](functional-spec.md)。この文書は「どの画面に何を出し、何ができるか」を書く

画面を変えるときは、この文書を直してから実装に反映する。

## 1. 共通

### 1.1 レイアウト

- 主な利用はスマホ。PC もスマホ幅（480px）の画面を中央に置き、画面幅 1024px 以上で左右の余白に左メニュー・右案内を出す。画面の中に PC 専用のレイアウトは作らない
- 色はブランドの2色（濃 `#3AD1CE`、淡 `#86E4E4`）と、キャラクター由来のオレンジを3色目に使う（[../brand/README.md](../brand/README.md)）
- キャラクター（ポイフォックス）は説明系のセクションや案内に使う。案件カードなど API の一覧には入れない
- 見出しは、説明系のセクションは中央揃え、一覧系は左に線を付ける

### 1.2 ヘッダー

- 左にロゴ（トップへ）
- 未ログイン: 「ログイン」
- ログイン中: **表示名と利用可能ポイント**（例「山田 さん 1,250pt」）。押すとマイページ（S09）へ
- お知らせアイコン: S22 へ。ログイン中は未読の数をバッジで出す（99件を超えたら「99+」。[機能仕様 11.1](functional-spec.md#111-お知らせ2026-11-26-yamada-決定)）
- お気に入りアイコン: ログイン中だけ出す。S24 へ
- メニューボタン: 会員メニューを開く（下の表）

| 会員メニュー | 未ログイン | ログイン中 |
|---|---|---|
| 案件を探す／イベント／担当サポート | ○ | ○ |
| マイページ（ポイント通帳） | | ○ |
| お気に入り（S24） | | ○ |
| お知らせ（S22） | ○ | ○ |
| ポイント交換 | | ○ |
| 登録情報（S21） | | ○ |
| ヘルプ・お問い合わせ | ○ | ○ |
| ログイン | ○ | |

「ポイント履歴」はマイページの通帳に入れたのでメニューに置かない。メニュー上部の残高欄のボタンは「ポイント交換」「ポイント通帳」。

### 1.3 左メニュー・右案内（PC 1024px 以上）

| 場所 | 内容 |
|---|---|
| 左メニュー | コピー「ひとりじゃない、あたらしいポイ活。」、トップ／案件を探す／イベント／担当サポート／はじめての方へ・ヘルプ。ログイン中はマイページ／ポイント交換／登録情報、未ログインはログイン |
| 右案内 | 未ログイン: 「登録無料！LINEですぐ始められます」＋「LINEで無料で始める」。ログイン中: 「今日もポイントを貯めよう」＋「案件を探す」。共通: 担当サポート（公式LINEで相談する）、はじめての方へ |

### 1.4 フッター

サービスについて・ヘルプ／利用規約／プライバシーポリシー／運営者情報／お問い合わせ、© POIFO

### 1.5 スマホの追従ボタン

- スマホで、未ログインのときだけ画面下に「LINEで無料で始める」を追従させる
- ログイン必須のページ・ログイン・認証まわりの画面（検索に出さない画面）には出さない

### 1.6 ログイン必須の画面

- 開いたときにログインを確かめ、確かめ終わるまで本文を出さない
- 未ログインならログイン画面へ移動する

### 1.7 読み込み・エラー

- API から取るところは「読み込み中…」を出してから中身に置き換える
- 取得できないときは「〜を読み込めませんでした。時間をおいて再度お試しください。」、0件のときは「〜はありません」「準備中です」を出す
- ログイン・マイページ・認証まわりは検索エンジンに出さない（noindex）

**ログイン中の並び**: 会員がすぐ案件を探せるよう、次の順にする。見た目は 2026-11-28 に届いたログイン後トップの見本（共有フォルダ `brand/redesign/mockup/top-member-mobile.png`、部品は `member-top/`）に寄せる。見本は値が仮なので画像は貼らず HTML/CSS で作る。角の波模様は作らない（yamada さん）。

1. 保有ポイントの帯: 左にコインの絵、「利用可能ポイント」と大きな数字、区切り線の右に「判定中 ○pt ＞」。押すとマイページ。帯の上に見出しは付けない（yamada さん）
1. 重要なお知らせ（あるときだけ1件。押すと S23。見本にはないが残す）
2. カテゴリから探す: ASP のカテゴリを件数の多い順に8件、4列のタイル（アイコン・カテゴリ名・件数）。アイコンはカテゴリ名に含まれる言葉で選ぶ（インストール＝ダウンロード、ゲーム・条件達成＝ゲーム機、カード、口座・証券＝銀行、購入・通販＝カート、有料＝人＋、会員・登録＝人、見積・査定＝リスト、資料・請求＝書類）。当てはまらない名前は値札のアイコン。押すと S02 をそのカテゴリで開く。**ログイン中は5行の案件メニューではなくこちら**（見本どおり）
3. おすすめ案件
4. みんなでポイ活！: 水色の囲みに見出し・「一覧を見る」・説明文「ゲーム案件などに、みんなで楽しく挑戦。イベント情報をチェックしよう！」・白いイベントカード（横スクロール）
5. 担当スタッフに相談: 見出し「困ったときは、担当スタッフに相談。」、説明文、「担当サポートについて」（S14）、右に絵（スマホ・吹き出し・人々。見本から切り出し）
6. よくある質問: 水色の囲み
7. ページの一番下ののぞき込むポイフォックス

初めての人向けの説明（ファーストビュー・特徴・貯め方・しくみ・最後の登録導線）はログイン中は出さない。

### S02 案件一覧

- 見出しの上に横長バナー `banner-wide-3-shopping`
- 見出し「案件を探す」と、「案件はログインしてから利用してください（ログインしていないとポイントが付きません）」の注意
- カテゴリのタブ（「すべて」が既定）。選ぶと URL に `?category=` を付ける（共有できる）
- トップの案件メニューから来たとき（`?featured=1`・`?tag=`・`?sort=points`）は、見出しをメニューの名前（例「ゲーム案件特集」）にし、その下にメニューの説明と「すべての案件を見る」を出す。カテゴリのタブは出さない。0件なら「（メニューの名前）は準備中です。」
- 案件カードを20件ずつ。続きは「もっと見る」
- 0件: 「現在掲載中の案件はありません。」

### S03 案件詳細

見た目は 2026-11-28 納品の見本（共有フォルダ `brand/redesign/campaign-detail/`）に寄せる。見本は値が仮なので HTML/CSS で作り、波模様は作らない（yamada さん）。上から:

1. 案件の頭: 角丸のアイコン、案件名、カテゴリ、掲載終了日（あるとき）。右にお気に入りボタン（☆、薄い水色の丸の中。押すたびに登録・解除し、画面下に「お気に入りに追加しました。」などを短く出す。未ログインならログイン画面へ）
2. ポイントの帯: ログイン後トップの帯と同じ形（コインの絵、区切り線、「最大 ○pt」）。定率でポイントが決まっていないときは「ポイントは獲得条件をご覧ください」
3. ボタン（帯のすぐ下）: ログイン中「この案件に進む →」（濃い色の丸いボタン。API 経由で広告主へ）／未ログイン「LINEでログインして進む」＋「ログインしないとポイントが付きません。」
4. 獲得条件とポイント（白いカード、見出しの左にクリップボードのアイコン）: 成果地点ごとに ● の行で「地点名：ポイント（判定まで約N日）」、その下に説明
5. 成果の条件・注意事項（白いカード、注意の三角のアイコン）: ASP の文面をそのまま
6. 案件の説明（白いカード、ゲームのコントローラのアイコン）: ASP の文面をそのまま。その下に i マーク付きの灰色の囲みで「ポイントは成果の発生後に『判定中』として表示され、広告主の承認後に利用できるようになります。」
7. 担当スタッフに相談（横長の小さいカード。ヘッドセットのアイコン、「困ったときは、担当スタッフに相談」、説明、「担当サポートについて →」→ S14）。yamada さんの決定で一枚絵の横長の形（素材04の縦長は使わない）

- 掲載していない案件: 「この案件は現在掲載されていません。」、ない ID: 「案件が見つかりません。」

### S04 イベント一覧

- 見出し「みんなでポイ活！イベント」と説明文
- イベントカードの一覧（並び順 → 開始日時順）。終了したものも残す
- 0件: 「イベントは準備中です。」

### S05 イベント詳細

- タイトル・サムネイル・日時・開催方法・定員（残り◯人）・参加特典（ポイント）・本文・注意事項
- 参加の欄は状況で出し分ける:

| 状況 | 表示 |
|---|---|

### S11 振込先口座の登録

- 入力: 氏名（漢字）／金融機関名／金融機関コード（4桁）／支店名／支店コード（3桁）／口座種別（普通・当座・貯蓄）／口座番号（7桁以内）／口座名義（カタカナ）
- 登録済みなら現在の口座を出す（口座番号は末尾3桁以外伏せる）。変更もこの画面
- 入力の誤りは項目ごとにエラーを出す。ほかの会員が登録済みの口座はエラー
- 登録後は銀行振込の申請画面（S20）へ戻り「振込先口座を登録しました。」
- 入口: S20（銀行振込）と S21（登録情報）

### S12 ポイント交換（交換先の一覧）

参考サイトに合わせ、交換先が1つでも一覧を出し、選んで詳細（S20）へ進む形にする。

- 利用可能ポイント
- 交換先の一覧（表示順）。各交換先に: アイコン・表示名・説明・最低交換ポイント・手数料・受け取りまでの目安（銀行振込は「月1回まとめて振込」）・受付停止の表示
- 交換先が増えて種類が多くなったら、カテゴリ（現金・ギフト券・電子マネーなど）で分けて出す
- データは `GET /v1/exchange-methods`。「受け取りまでの目安」（`delivery_note`）とカテゴリ（`category`）は交換先の設定（`config/poifo.php`）に持つ
- 下に「交換履歴を見る」（S09 の交換履歴タブへ）

### S20 交換先の詳細・申請

`/mypage/withdraw/detail/?method=<交換先コード>`。

銀行振込（`bank_transfer`）の場合:

- 交換先の説明・最低交換ポイント・交換レート・手数料・受け取りまでの目安
- 交換するポイントを入れると、受け取る金額（手数料があれば手数料も）を出す
- 口座が未登録: 「換金するには、先に振込先口座を登録してください。」＋「振込先口座を登録する」（S11）
- 登録済み: 振込先（伏せ字）、利用可能ポイント、交換するポイントの入力欄、申請ボタン、「振込先口座を確認・変更する」
- 注意: 「振込は月に1回まとめて行います。申請から振込まで、審査のため日数がかかります。」「申請したポイントは、申請の時点で残高から差し引かれます。審査の結果お振込みできない場合は、ポイントをお戻しします。」
- 申請後はこの画面で「交換を申請しました」（キャラクター付き）を出し、「交換履歴を見る」で S09 の交換履歴タブへ
- 受付停止の交換先は申請欄を出さず「現在、受付を停止しています。」
- 受け取り情報が要る交換先を足すときは、その交換先専用の登録画面を S11 と同じように作る

### S13 退会

- 「退会する前に必ずご確認ください。」と注意事項
  - 残っているポイント（利用可能・判定中とも）はすべて失効し、元に戻せません
  - 退会後は、同じ LINE アカウントでもう一度登録することはできません
  - 手続き中のポイント交換（申請中・振込待ち）があるときは退会できません
  - 参加予定のイベントがあっても参加特典は受け取れません
- 「上記を確認し、同意します」にチェック → 「退会する」→ 確認（「本当に退会しますか？この操作は取り消せません。」）
- 退会後はログアウトしてトップへ
