## 開発に効く要点

### 案件連携API
- `GET https://api.gf-rewards.com/media/v1/campaigns`、ヘッダー `api-key`、必須パラメータ `ad_channel_id`（掲載面ID）
- **1時間あたり60回まで**。ページ表示ごとに呼ばず、バッチで取得してDBに保存して配信する
- 案件ごとに成果地点（`conversion_actions`）、計測リンク（`click_url`）、重複排除条件、ステータス（not_started / started / paused）が返る

### クリック計測
- 計測リンクに `user_id={自社のユーザーID}` を付けて遷移させる。1ユーザーにつき1つのIDにする（LINEのユーザーIDは使わず内部IDにする）
- `media_session_1`（最大64文字）を付けると成果通知で同じ値が返る

### 成果通知（ポストバック）
- GET または POST（JSON）で届く。送信元IPは `35.74.33.32` と `35.74.215.16`。**IP制限を求められている**
- `hash`：「`user_id:cv_action_id:cv_datetime`」を、シークレットキー（メディアのAPIキー）を鍵にした **HMAC-SHA256** で計算した16進小文字。仕様書の例（キー `test`）の値 `e64ab9be…` と一致することを確認済み。照合して不正リクエストを弾く
- `cv_status`：0=未承認、1=承認、2=否認。未承認でも通知が来るので、ポイントは「判定中」として扱い、承認で確定する
- `cv_id` で重複チェック必須
- レスポンスは HTTP 200 で本文に `0`（未付与）/ `1`（付与）/ `2`（未付与・退会ユーザー）のみ
- 失敗（接続不可・200以外・10秒超）で最大4回リトライ（計5回）

### 不正対策（換金系サイトへの要請）
未実施で不正が発覚すると成果報酬が支払われない可能性があります。
- 1端末1アカウント（電話番号認証など）
- 退会→再入会での再利用防止（利用履歴の引き継ぎ）
- 同一口座の複数ユーザー利用禁止、口座名義が同じユーザーの検知
- 換金申請から換金までの審査期間

### オファーウォール
- `https://ow-gf-rewards.com/{コンテンツID}?userId=...&digest=...` で GF 側の案件一覧画面を表示する方式
- サンドボックスはなく、本番のオファーウォール上のテスト用キャンペーンで連携テストを行う
